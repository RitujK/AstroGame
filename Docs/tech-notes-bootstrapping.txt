Mission 1 technical notes
- Texture: earth-equirectangular.jpg on a UV sphere Mesh; procedural canvas fallback if load fails.
- Rotation: horizontal pointer delta subtracts from globeRotation so the front face follows the cursor.
- Mesh: modelRotation.y = −globeRotation; geometry + mirrored UVs keep east on screen-right.
- Cities: lat/lon orthographic projection; pins hide on the far hemisphere.
- Day = sunward X of the city > threshold (Sun along +X / right).
- Checklist is screen-space; completion requires interaction then all three targets matched.
- Success copy fades in (no scale tween).

Mission 2 technical notes
- Moon angle from orbit drag (atan2 around Earth) or from the year-style slider (0–360).
- Phase disc lighting from the +X sun; “view from Earth” panel mirrors the same angle.
- Lock In compares angle to the challenge target within tolerance, then advances.

Mission 3 technical notes
- Orbit angle: 0° = December (Earth right of Sun), 180° = June (Earth left). Drag uses pointer polar angle around the Sun (ellipse-normalized); release snaps to 90° stops. Month chips set the same angles.
- Tilt: continuous 0–45°; lock requires ~15–32° (Earth-like).
- Season model: nhScore = −cos(orbitAngle) * tiltStrength so Dec = NH winter, Jun = NH summer; SH is the negation.
- Visual axis: axisAngle = −π/2 + lean so the N tip leans right (Dec = away from Sun, Jun = toward). Axis stays parallel around the orbit.
- Earth is the same sphere mesh; auto-spin on Y is decorative only.
- Single pointermove / pointerup handles globe, orbit slider, and tilt slider.

Mission 4 technical notes
- Catalog projects J2000 RA/Dec into a unit square for New Delhi · March (northern) and Cape Town · September (southern).
- Six definitions: orion, ursa-major, cassiopeia, leo, crux, scorpius.
- Tracing: click stars to add undirected edges; match the definition’s edge set.
- On success: show atlas PNG with per-constellation placement (Scorpius uses head→stinger axis fit). Square frame so stars and art scale together on desktop/mobile.
- No post-complete depth animation (it warped shapes). No nebula ellipses (they read as ovals).
- Star names appear after the pattern is complete.

Mission 5 technical notes
- Data: `engine/data/planets.ts` — Mercury→Neptune with kid-scale radii, `PlanetVisual` recipes (bands/craters/caps/grain/spots/rings/spin), five scan features (Mercury, Earth, Mars, Jupiter, Saturn).
- Phase 1 (assemble): scrambled dock; drag onto concentric orbits; release snaps to nearest ring; Lock In when all eight match order 0…7.
- Phase 2 (scan): bottom-bar target readout (same band as the dock); unscanned feature worlds get pulse + bracket highlights; tap match → cinematic close-up (vignette, reticle, sweep) + fact card + Continue in that bar. Header shrinks to objective + counter during the tour.
- Rendering: each planet is a sphere Mesh with an equirectangular surface baked at runtime (Earth uses earth-equirectangular.jpg). Nebula baked at 1024×576.
- Lighting per frame from the Sun: atmosphere halo, graded terminator + sunward rim. Far-side worlds occluded by the corona skip shading.
- Saturn rings: tilted squashed ellipse, behind/in-front layers, Cassini gap.
- Formation: shared `systemPhase` + golden-angle step per slot (`FORMATION_STEP`) so relative spacing never collapses while revolving. Tap hit circles are depth-sorted; compact layouts use tighter grab padding. Spacing verified via `scripts/check-orbit-spacing.mjs`.
- Orbit depth is adaptive: portrait phones open the plane (ORBIT_DEPTH_RANGE.compact ~0.42–0.62); desktop stays flatter (wide ~0.34–0.44). Header stacks from measured text heights with one glyph inset.
- Theme-aware chrome; reduced-motion disables formation drift, scan pulse, and star twinkle.
